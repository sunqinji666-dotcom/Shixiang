# 拾响 · 后续性能根因优化计划

## 本次发布边界

- 当前发布候选保留现有窗口缩放体验方案，不再把新的性能重构混入本次发布。
- `live resize shell` 是窗口拖拽期间的临时体验缓解：用轻量内容降低实时重排压力，但它不是最终方案。
- 根因优化另开后续版本完成，避免发布前的大范围结构调整引入新回归。

## 后续目标

窗口拖动四边或四角时继续显示真实界面内容，并保持顺滑响应；不依赖静态骨架替换，不出现明显闪烁，也不丢失列表、播放、波形和搜索状态。同时降低日常浏览、搜索和播放时的主线程压力与内存占用。

## 重点排查方向

1. 用 Instruments 和可复现基准定位窗口缩放时的主线程热点，分别记录 CPU、内存、掉帧和视图重建次数。
2. 检查 `HSplitView`、`List`、`GeometryReader` 在窗口尺寸变化时是否触发过量布局和整棵视图重建。
3. 检查侧栏目录树、分类数量、隐藏数量和索引数量是否在每次 resize 回调中重复计算。
4. 检查 `WaveformView` 的 Canvas、播放进度刷新及 `TimelineView` 是否在缩放期间争抢主线程。
5. 审计隐式 `.animation`，避免动画错误覆盖连续窗口尺寸变化和大列表布局。
6. 检查搜索快照、预加载、缓存清理、索引和声学分析任务是否与窗口缩放争用 CPU 或产生过密的主线程回调。
7. 若 SwiftUI 容器仍无法稳定控制重排边界，评估由 AppKit 承载窗口分栏和列表外壳，SwiftUI 继续负责业务组件。
8. 进一步优化结构化搜索索引，避免反复为全库重建 CJK n-gram 和中间数据。

## 预计投入

- 定位卡顿源：20–40 分钟。
- 窗口布局与刷新边界重构：1–2 小时。
- 编译、交互与状态回归：约 1 小时。
- 如需改用 AppKit 容器：额外 1–2 小时。
- 预计 2–3 小时解决主要缩放卡顿；约 4–6 小时完成包含搜索、缓存和后台任务在内的全局性能优化与量化验收。

## 验收标准

- 拖动窗口四边和四角时，真实内容持续显示且可辨识。
- 不出现骨架替换、明显闪烁、旧行残影或列错位。
- 缩放前后的选中声音、滚动位置、搜索条件、播放进度和波形状态保持正确。
- 缩放后播放器、拖拽、搜索、筛选及侧栏展开状态无回归。
- 用固定资料库和固定操作脚本记录优化前后的 CPU 峰值、内存峰值、掉帧情况和恢复到空闲的耗时。

## 发布候选约束

- 当前交付目标为 Apple Silicon Mac。
- 当前最低系统版本以 `Support/Info.plist` 为准：macOS 14.0 或更高；本地 AI 自然语言搜索单独要求 macOS 26.2 或更高。
- 本次正式交付只做构建、签名/启动验证、安装引导和交付包检查；上述性能根因重构留到下一版本。
